# Milestone 5B — experimental webcam-assisted tracking

Implementation status: restricted assistance is implemented; physical reliability acceptance is **pending**. No real-camera accuracy, false-positive rate, or physical turn-latency claim has been established. User indicated a physical cube is available; real six-face scan feedback and annotated tracking captures have not yet been received. Synthetic tests below do not satisfy that physical gate.

## Behavior and architecture

Browser video-only capture reuses 5A's explicit permission, unmirrored crop, stream cleanup and local processing. OpenCV detects nine separated sticker quadrilaterals, estimates their convex face envelope, rectifies by homography, and estimates a planar PnP pose. Camera intrinsics are an approximation (focal=max(width,height), centered principal point, no distortion); this is not calibrated 3D cube pose. Face identity and in-plane cube axes are user locked with current-grip adjacent-center instructions. Heavy tilt, roll >15°, low sharpness, inconsistent geometry, occlusion and low sticker confidence suspend logging. False shape detections remain possible, so the UI requires operator confirmation.

Each observed face is classified against the reviewed six-center Lab calibration. Match its nine observed stickers to canonical successors for no action, 18 outer face turns, and 9 grip rotations. Require all nine confidence scores >=0.6 and three consistent observations within 1.5 seconds each. This is a bounded **one-action hypothesis pool**, not proof of a unique physical history. An unchanged visible face can conceal back-face turns; no-change observations log no moves. Hidden/multiple turns cannot be silently inferred. Every accepted action requires explicit confirmation that exactly it occurred and no other turns happened. Automatic commit is always false.

Server confirms only fresh (<30 seconds), latest, stable evidence at the accepted state's hash, matching one legal candidate. Revision checks and SQLite write transactions reject racing/double submissions. Engine before/after hashes validate reconstruction. Candidate observations leave state unchanged. Stop/background/face changes mark uncertainty; a pending observation queues its gap after its acknowledged revision. Reloads serialize with mutations and force alignment recovery. Abrupt process/page exit can prevent a final gap request; reopening still requires a new-clock recovery boundary and all physical timing remains uncertain.

Recovery offers explicit manual known corrections/alignment or a new complete guided scan with new calibration. Unknown moves are never filled in. A gap and resync checkpoint preserve previous evidence and split analysis into independent segments. Original initial state and calibration remain immutable; replacement states/calibration live in append-only events. Session size is bounded to 4,096 evidence events; recovery reserves two slots and ending remains available at the cap.

Migration 002: `camera_sessions` stores initial state, initial calibration, version and creation time; `camera_events` stores ordered observation/confirmation/gap/resync/stop records, clock UUID and monotonic client observation/confirmation timestamps. Observations store pose, labels, confidence, candidate matches, processing time and frame hash, never image bytes. Event provenance distinguishes operator-confirmed action from measured observation. `physical_turn_at_ms` stays null. Reports withhold physical total moves, TPS and stage durations. Manual PB/dashboard averages exclude camera sessions.

Camera analysis reuses deterministic prerequisite-aware CFOP checkpoint analysis within each contiguous confirmed segment with timing disabled. Exact state checkpoint replay, HTM/rotations, and retrospective comparisons are available; no reconstruction crosses gaps. Raw newly attained piece predicates are displayed as such, not human recognition times. Confirmed HTM counts describe logged canonical actions, not guaranteed total physical turns.

## Measurement protocol

Optional **Begin measurement burst** retains up to the first 30 real captured JPEG frames in memory, using the session's actual calibration, face, exact accepted initial state and browser frame timestamps. Choose actual action independently of recommendations (or unknown/no-turn), then explicitly export the JSON. New mutations/recovery stop the burst; normal operation does not retain photos. Export does not create performance records.

`cubiq/scripts/evaluate-camera.py MANIFEST` accepts operator-declared physical webcam datasets. `--allow-controlled-test` is required to evaluate explicitly synthetic data. Each case contains `id`, `initial_facelets`, `calibration`, `face`, `actual_action` (notation, empty no-turn, or null unknown), and `frames` with `at_ms` plus inline `image` or relative `file`. Optional `annotated_turn_complete_ms` must be independently annotated in that same timestamp clock. Example shape (not an actual measurement):

```json
{"dataset_kind":"physical-webcam","cases":[{"id":"operator-trial-1","initial_facelets":"<54 reviewed identities>","calibration":{"U":[0,0,0],"R":[0,0,0],"F":[0,0,0],"D":[0,0,0],"L":[0,0,0],"B":[0,0,0]},"face":"F","actual_action":"R","frames":[{"file":"actual-capture.jpg","at_ms":1000}]}]}
```

The illustrative placeholder calibration above is deliberately invalid; use real exported calibration. Report distinct suggestion episodes, conditional scored accuracy, false suggestions (including early wrong episodes even if later corrected), abstentions, measured processing time, and delay to the first correct suggestion when a completion annotation exists. Unknown ground truth is not scored correct. No automatic commits is a design property, not measured camera accuracy. Frame evidence delay excludes network/browser transport and is not universal tracking latency.

Real acceptance still needed: several legal mixed scrambles and all face-turn directions, different viewpoints/lighting, controlled no-turn intervals, hands/occlusions, fast multi-turn intervals, deliberate hidden moves, and manual/rescan recovery; independent action/turn-end annotations. Record sample counts, conditional suggestion precision, abstention rate, false suggestions, latency distribution and recovery success. A six-face successful scan alone does not demonstrate live-tracking reliability.

## Automated acceptance

Controlled JPEGs exercise actual OpenCV, calibration, plane/PnP, blur/occlusion abstention and temporal stability. All 28 action hypotheses across six face views (168 cases) include the actual canonical transition. Tests prove no observation commits, exactly-once explicit confirmation, stale/expired/unsupported/unconfirmed rejection, clock-change recovery, SQLite reopen, gap/rescan preserved history, two independently reconstructed retrospective segments, bounded-event recovery/end behavior, and retained false-suggestion/first-correct-latency scoring. UI tests prove confirmation gating, queued gaps during in-flight observation, stale evidence hidden after recovery, and serialized reload. Fixtures are explicitly synthetic and confined to tests.
